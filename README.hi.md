एक रेपो-नेटिव ऑपरेटिंग लेयर जो 61 विशिष्ट भूमिका अनुबंधों के माध्यम से कर्मचारियों, मार्गों, मान्यताओं और कोडिंग-एजेंट कार्यों को चलाती है। यह कार्य पैकेट बनाता है, स्कोर किए गए भूमिका मिलान से सही टीम को इकट्ठा करता है, निष्पादन से पहले टूटी हुई श्रृंखलाओं का पता लगाता है, जब कार्य अवरुद्ध या अस्वीकृत हो जाता है तो स्वचालित रूप से पुनर्प्राप्ति मार्ग प्रदान करता है, और प्रत्येक निर्णय में संरचित प्रमाण की आवश्यकता होती है। इसमें मैनिफेस्ट-स्केल्ड मिशनों के लिए गतिशील डिस्पैच शामिल है - एक 10-घटक रेपो स्वचालित रूप से 28 ऑडिटर चरणों में बदल जाता है, न कि 6।

क्लॉड कोड एडाप्टर शिप (`roleos init` स्केफोल्ड `.claude/`)। अनुबंध मार्कडाउन हैं, जिन्हें कोई भी कोडिंग हार्नेस उपयोग कर सकता है - यह रेपो यह दावा नहीं करता है कि एक दूसरा एडाप्टर पहले से ही चल रहा है।

## यह क्या करता है

रोल ओएस कोडिंग-एजेंट कार्यों के लिए कर्मचारियों को नियुक्त करने का एक पेशेवर तरीका है। यह उन विशिष्ट विफलताओं को रोकता है जो सामान्य एआई वर्कफ़्लो उत्पन्न करते हैं:

- **विचलन** - भूमिकाएँ अपनी सीमा में रहती हैं। उत्पाद फिर से डिज़ाइन नहीं करता है। फ्रंटएंड दायरे को फिर से परिभाषित नहीं करता है। बैकएंड उत्पाद दिशा का आविष्कार नहीं करता है।
- **गलत पूर्णता** - पूर्णता की परिभाषा ठोस है। वह कार्य जो अंतराल को छिपाता है, सत्यापन को छोड़ देता है, या किसी भिन्न समस्या को हल करता है, उसे अस्वीकार कर दिया जाता है।
- **संदूषण** - फोर्क या विरासत में मिली परियोजनाओं में पहचान अवशेष होते हैं। रोल ओएस शब्दावली, दृश्यों और मानसिक मॉडलों में क्रॉस-प्रोजेक्ट विचलन का पता लगाता है और उसे अस्वीकार कर देता है।
- **भावना-आधारित प्रगति** - प्रत्येक हैंडऑफ़ संरचित है। प्रत्येक निर्णय प्रमाण से जुड़ा है। "यह पूरा हो गया है" एक मान्य स्थिति नहीं है।

## यह कैसे काम करता है

अपने कार्य का वर्णन करें। रोल ओएस स्वचालित रूप से सही स्तर के ऑर्केस्ट्रेशन का निर्णय लेता है।

```bash
roleos start "fix the crash in save handler"
# → MISSION: Bugfix & Diagnosis (70% confidence)
#   Chain: Repo Researcher → Backend Engineer → Test Engineer → Critic Reviewer

roleos start "add a new export command"
# → PACK: Feature Build (50% confidence)
#   Roles: Orchestrator, Product Strategist, Spec Writer, Backend Engineer, Test Engineer, Critic Reviewer

roleos start "something completely novel"
# → FREE-ROUTING (10% confidence)
#   Hint: Create a packet and run `roleos route` for role-level routing
```

**बैकअप सीढ़ी:**

1. **मिशन** - जब कार्य एक सिद्ध आवर्ती वर्कफ़्लो (बगफिक्स, उपचार, सुविधा-शिप, दस्तावेज़, सुरक्षा, अनुसंधान, विचार-मंथन, गहन-ऑडिट, डॉगफूड-स्वार्म) से मेल खाता है। ज्ञात भूमिका श्रृंखला, कलाकृति प्रवाह, वृद्धि शाखाएँ और ईमानदार-आंशिक परिभाषाएँ।
2. **पैक** - जब कार्य एक ज्ञात परिवार होता है लेकिन पूर्ण मिशन आकार नहीं होता है। 10 कैलिब्रेटेड टीम पैक, जिसमें ऑटो-चयन और बेमेल गार्ड होते हैं।
3. **मुक्त रूटिंग** - जब कार्य नया, मिश्रित या अनिश्चित होता है। यह सभी 61 भूमिकाओं को पैकेट सामग्री के विरुद्ध स्कोर करता है और एक गतिशील श्रृंखला को इकट्ठा करता है।

यह प्रणाली कभी भी कार्य को गलत अमूर्तता के माध्यम से मजबूर नहीं करती है। यह बताता है कि इसने प्रत्येक स्तर को क्यों चुना और विकल्प प्रदान करता है।

**सक्रिय निष्पादन के लिए एक कमांड:**

```bash
roleos run "fix the crash in save handler"
# → Created run: run-1234
# → Entry: MISSION (bugfix)
# → Started step 0: Repo Researcher → diagnosis-report
# → Guidance: Required sections: entrypoints, module-map, build-test-commands

roleos next                    # Start the next step
roleos complete diagnosis.md   # Complete the active step with artifact
roleos explain                 # Show full run state and guidance
roleos resume                  # Continue an interrupted run
roleos report                  # Generate completion report
roleos friction                # Measure operator touches
```

**जब चीजें गलत हो जाती हैं तो हस्तक्षेप:**

```bash
roleos retry 0                 # Retry a failed step
roleos reroute 1 "Frontend Developer" "UI bug"  # Swap a role
roleos escalate "Test Engineer" "Repo Researcher" "missed edge case" "re-diagnose"
roleos block 2 "waiting for API spec"
roleos reopen 0 "found issue in review"
```

कार्य डिस्क पर बने रहते हैं (`.claude/runs/`), इसलिए बाधित सत्रों को साफ-सुथरा तरीके से फिर से शुरू किया जाता है। प्रत्येक चरण में ऑपरेटर मार्गदर्शन शामिल होता है: क्या उत्पन्न करना है, आवश्यक अनुभाग और समाप्ति शर्तें।

**एक बार रूट किए जाने के बाद:**

1. **प्रत्येक भूमिका एक हैंडऑफ़ उत्पन्न करती है** - संरचित आउटपुट जिसमें प्रमाण आइटम होते हैं जो अगली भूमिका के लिए अस्पष्टता को कम करते हैं।
2. **आलोचक अनुबंध के विरुद्ध समीक्षा करते हैं** - संरचित प्रमाण के आधार पर स्वीकार, अस्वीकार या अवरुद्ध करते हैं, न कि धारणा के आधार पर।
3. **पुनर्प्राप्ति मार्ग स्वचालित रूप से** - अवरुद्ध या अस्वीकृत कार्य को एक कारण, पुनर्प्राप्ति प्रकार और आवश्यक कलाकृति के साथ सही समाधानकर्ता को रूट किया जाता है।

## बजट-जागरूक डिस्पैच

रोल ओएस प्रत्येक डिस्पैच चरण के लिए एक स्थानीय **टोकन बजट विश्लेषक** से परामर्श कर सकता है और मैनिफेस्ट से एक सलाहकार व्यय पूर्वानुमान संलग्न कर सकता है - वैकल्पिक (`ROLEOS_BUDGET_CONSULT`), सलाहकार (यह कभी भी डिस्पैच को अवरुद्ध नहीं करता है), और एक नियतात्मक आधार रेखा पर विफल-खुला। डिफ़ॉल्ट रूप से बंद; पूर्वानुमान स्थानीय है और चलाने के लिए स्वतंत्र है। [हैंडबुक](https://mcp-tool-shop-org.github.io/role-os/handbook/specialist-budget/) देखें।

## टूल-कॉल निरीक्षण

रोल ओएस `PreToolUse` सीम पर टूल कॉल को सत्यापित और गेट करता है - नियतात्मक रूप से, बिना किसी मॉडल के गर्म पथ पर:

- **अनुरूपता वॉचर** (सलाहकार, विफल-खुला) - एक नियतात्मक स्कीमा + संगणनीय-अनुबंध तल एक प्रस्तावित कॉल की तुलना इसके कैटलॉग किए गए टूल-अनुबंध से करता है और एक *सिद्ध* गैर-अनुरूप कॉल पर एक सलाहकार निर्णय संलग्न करता है; यह कभी भी अवरुद्ध नहीं करता है। एक वैकल्पिक एलएलएम छत (`ROLEOS_CONFORMANCE_CONSULT`) वास्तव में-सिमेंटिक अवशेष को संभालता है।
- **क्षमता गेट** (विफल-बंद, वैकल्पिक `ROLEOS_CAPABILITY_GATE`, डिफ़ॉल्ट रूप से बंद) - *अपरिवर्तनीय* कार्यों (एनपीएम/पाइपी प्रकाशित करें, `gh release`, `git push`, रेपो संपादन, पेज तैनात करें) पर नियतात्मक न्यूनतम-अधिकार। एक गेटेड कार्रवाई को तब तक अस्वीकार कर दिया जाता है जब तक कि निदेशक ने `.claude/role-os/capabilities.json` में इसकी क्षमता प्रदान नहीं की है, इसलिए एक गलत कदम - एक ईमानदार गलती या एक इंजेक्ट की गई गलती - एक अनधिकृत अपरिवर्तनीय कार्रवाई को ट्रिगर नहीं कर सकता है। नामित-क्षतिपूर्ति नियम का निवारक पूरक। [हैंडबुक](https://mcp-tool-shop-org.github.io/role-os/handbook/) देखें।

## क्रू डोजियर

प्रत्येक भूमिका में एक **डोजियर** होता है - एक चरित्र शीट जो रन-टाइम कॉन्फ़िगरेशन के रूप में दोगुनी होती है। छह योग्यताएँ (कठोरता, गति, दायरा, संशयवाद, स्वायत्तता, ईमानदारी) वास्तविक डिस्पैच नॉब्स से मेल खाती हैं; एक आठ-आर्केटाइप **प्रवृत्ति** परत (संशयवादी, बिल्डर, अन्वेषक, मावेरिक...) एक व्यवहारिक निर्देश ले जाती है; और प्रत्येक भूमिका में एक चित्रित चित्र और एक ग्रेड होता है। पूरे क्रू को एक गैलरी के रूप में ब्राउज़ करें (`dossier/dossier.html`) - प्रत्येक भूमिका का रडार इसकी आदर्श आदर्श के विरुद्ध इसके ट्यून किए गए निर्माण को दिखाता है।

जब किसी भूमिका में एक डोजियर होता है, तो डिस्पैच एक **ऑपरेटिंग मुद्रा** इंजेक्ट करता है - प्रवृत्ति का व्यवहारिक निर्देश और भूमिका की योग्यताओं से एक मुद्रा पंक्ति - इसलिए शीट वास्तव में भूमिका को कॉन्फ़िगर करती है। वैकल्पिक और अतिरिक्त: बिना डोजियर वाली भूमिकाएँ बिल्कुल पहले की तरह व्यवहार करती हैं। [हैंडबुक](https://mcp-tool-shop-org.github.io/role-os/handbook/crew-dossier/) देखें।

## संगठनात्मक रोलआउट स्थिति

संगठन-व्यापी रोलआउट स्थिति (कतार, निर्णय, ऑडिट रिकॉर्ड, प्रति-रेपो लॉक पैकेट) एक अलग **निजी**, संगठन-आंतरिक रेपो (`role-os-rollout`) में रहती है। यह रेपो उत्पाद है; वह रेपो परिचालन स्थिति है।

## स्मृति और निरंतरता

रोल ओएस स्मृति परत का स्वामित्व या डुप्लिकेट नहीं करता है। जहां एक हार्नेस प्रोजेक्ट-मेमोरी स्टोर मौजूद है, यह कैनोनिकल निरंतरता प्रणाली है - रेपो तथ्य, निर्णय, खुले लूप और उपचार इतिहास वहां रहते हैं।

रोल ओएस जब मौजूद हो तो उस स्टोर के साथ एकीकृत होता है। यह इसे प्रतिस्थापित नहीं करता है।

## पूर्ण उपचार और शिपचेक

पूर्ण उपचार एक मानक 7-चरण प्रोटोकॉल है जिसे स्टूडियो प्रोजेक्ट मेमोरी में परिभाषित किया गया है (`memory/full-treatment.md`)। रोल ओएस भूमिका अनुबंधों, हैंडऑफ़ और क्रिटिक गेट्स का उपयोग करके भूमिकाओं को रूट करता है और उपचारों की समीक्षा करता है - यह प्रोटोकॉल को फिर से परिभाषित नहीं करता है।

**शिपचेक** 31-आइटम गुणवत्ता गेट है जो पूर्ण उपचार से पहले चलता है। किसी भी उपचार को शुरू करने से पहले हार्ड गेट A-D को पास करना होगा। मानक संदर्भ: `memory/shipcheck.md`।

क्रम: पहले शिपचेक, फिर पूर्ण उपचार। हार्ड गेट्स को पास किए बिना v1.0.0 नहीं।

प्रत्येक भूमिका में एक पूर्ण अनुबंध होता है: मिशन, उपयोग कब करें, उपयोग कब न करें, अपेक्षित इनपुट, आवश्यक आउटपुट, गुणवत्ता बार और वृद्धि ट्रिगर। प्रत्येक भूमिका रूट करने योग्य है - `roleos route` पैकेट सामग्री के आधार पर उनमें से किसी की भी सिफारिश कर सकता है।

## त्वरित शुरुआत

```bash
# Install (puts `roleos` on your PATH):
npm install -g role-os

# Scaffold the role spine into your repo:
roleos init
# (one-off alternative without installing: `npx role-os init`,
#  then prefix every command below with `npx role-os` instead of `roleos`)

# Describe what you need — Role OS picks the right level:
roleos run "fix the crash in save handler"
# → Creates run, picks bugfix mission, starts first step with guidance

# Step through:
roleos next                    # Start next step
roleos complete artifact.md    # Complete with artifact
roleos explain                 # Show full state
roleos report                  # Completion report

# Deep audit:
roleos audit manifest --generate   # Create audit-manifest.json
roleos audit                       # Start component-level deep audit
roleos audit status                # Check audit progress
roleos audit verify                # Verify manifest and outputs

# Dogfood swarm:
roleos swarm manifest --generate   # Auto-detect domains from repo structure
roleos swarm                       # Start multi-pass convergence swarm
roleos swarm status                # Check swarm progress by stage
roleos swarm findings              # List findings by severity
roleos swarm approve               # Approve feature gate

# Or go manual:
roleos start "fix the crash"   # Entry decision only (no run)
roleos packet new feature
roleos route .claude/packets/my-feature.md
roleos review .claude/packets/my-feature.md accept

# Explore missions and packs:
roleos mission list
roleos packs list
```

## रोल ओएस का उपयोग कब न करें

- एकल-पंक्ति सुधार, टाइपो या स्पष्ट बग
- कोई परिभाषित आउटपुट नहीं होने पर अन्वेषणात्मक अनुसंधान
- वह कार्य जो 5 मिनट में किसी एक व्यक्ति के दिमाग में फिट हो जाए
- आपातकालीन हॉटफिक्स जिन्हें समीक्षा श्रृंखला पूरी होने से पहले शिप करने की आवश्यकता होती है
- ऐसे प्रोजेक्ट जहां आप संरचना से अधिक गति चाहते हैं

## सबूत

रोल ओएस को दो संरचनात्मक रूप से भिन्न रिपोज़ में तीन परीक्षण आकृतियों में साबित किया गया:

**परीक्षण 001 - सुविधा कार्य** (क्रू स्क्रीन, स्टार फ्रेट)
- 7-भूमिका श्रृंखला, 45 परीक्षण परिदृश्य, 0 भूमिका टकराव
- फोर्क पूर्वज से संदूषण को रोका, इनलाइन आविष्कार को पकड़ा, ईमानदार अवरोधकों को उजागर किया

**परीक्षण 002 - एकीकरण कार्य** (कैंपेनस्टेट वायरिंग, स्टार फ्रेट)
- 5-भूमिका श्रृंखला, बिना किसी फॉलबैक झूठ के वास्तुशिल्प सीम को हल किया
- एंटी-फॉलबैक परीक्षणों ने साबित किया कि लाइव पथ वास्तविक है, न कि एक प्लेसहोल्डर

**परीक्षण 003 - पहचान कार्य** (संदूषण शुद्धिकरण, स्टार फ्रेट)
- 6-भूमिका श्रृंखला, 51 परीक्षण परिदृश्य जिसमें टिकाऊ सीआई संदूषण रक्षा शामिल है
- व्यापक पुनर्निर्माण में ढहने के बिना विरासत में मिली काल्पनिक विचलन को ठीक किया

**पोर्टेबिलिटी परीक्षण** (व्यक्तित्व स्थिरता, सेंसर-हास्य)
- समान रीढ़, अलग भाषा/डोमेन/स्टैक
- केवल संदर्भ परिवर्तनों के साथ अपनाया गया - कोई मूल अनुबंध संशोधन नहीं

**पूर्ण उपचार FT-001** (पोर्टलाइट-डेस्कटॉप)
- उपचार पैक भूमिकाओं के साथ 7-चरण वाला स्टाफ उपचार
- शिपचेक गेटिंग सिद्ध, शून्य भूमिका टकराव

**पूर्ण उपचार FT-002** (स्टूडियोफ्लो)
- समान उपचार पैक, संरचनात्मक रूप से भिन्न रिपो (रचनात्मक कार्यक्षेत्र बनाम गेम)
- उपचार पैक पोर्टेबल - कोई अनुबंध संशोधन आवश्यक नहीं

**विचार-मंथन का सुनहरा दौर** (एमसीपी सर्वर मार्केटप्लेस विषय)
- 9-भूमिका श्रृंखला, 4 विश्लेषक समानांतर में, क्रॉस-जांच + खंडन विवाद ग्राफ
- 4 चुनौतियाँ जारी की गईं, 3 दावों को संकुचित किया गया, 1 अनसुलझा - स्वस्थ दबाव, गतिरोध नहीं
- प्रस्तुत कलाकृतियों से सत्य-परत परमाणुओं तक 16+ ट्रेस लिंक
- श्रृंखला की पूरी कस्टडी सिद्ध: सत्य → परमाणु → विवाद → संश्लेषण → विस्तार → न्यायाधीश → प्रस्तुत → ट्रेस

## सुरक्षा

डिफ़ॉल्ट रूप से, रोल ओएस केवल **स्थानीय फ़ाइल सिस्टम** पर काम करता है। यह मार्कडाउन टेम्पलेट की प्रतियां बनाता है और आपके रिपॉजिटरी की `.claude/` निर्देशिका में पैकेट/निर्णय/रन फ़ाइलें लिखता है। डिफ़ॉल्ट संचालन कोई नेटवर्क अनुरोध नहीं करता है, कोई रहस्य नहीं संभालता है, और कोई टेलीमेट्री एकत्र नहीं करता है। कोई खतरनाक संचालन नहीं - सभी फ़ाइल लेखन डिफ़ॉल्ट रूप से स्किप-इफ-एग्ज़िस्ट का उपयोग करते हैं।

तीन **ऑप्ट-इन** सुविधाएँ हैं जो तब नेटवर्क को स्पर्श करती हैं जब आप उन्हें स्पष्ट रूप से सक्षम करते हैं:

- **`roleos verify-citations`** - यह बाहरी `prism` सीएलआई पर शेल करता है, जो सार्वजनिक arXiv/Crossref एपीआई के विरुद्ध उद्धरण पहचानकर्ताओं को हल करता है (सत्यापित किए जा रहे उद्धरण आईडी/यूआरएल भेजता है)।
- **विशेषज्ञ स्तर** (`roleos specialist`, पंजीकृत भूमिकाएँ) - यह `.role-os/specialists.json` में आपके द्वारा कॉन्फ़िगर किए गए `backend_url` को डिस्पैच प्रॉम्प्ट पोस्ट करता है (आमतौर पर एक स्थानीय मॉडल एंडपॉइंट)।
- **बजट / अनुरूपता परामर्श** (`ROLEOS_BUDGET_CONSULT` / `ROLEOS_CONFORMANCE_CONSULT`) - यह एक सलाहकार निर्णय के लिए एक स्थानीय मॉडल को एचटीटीपी पर चरण/टूल-कॉल संदर्भ भेजता है।

तीनों डिफ़ॉल्ट रूप से बंद हैं और स्थानीय नियतात्मक व्यवहार के लिए खुले रहते हैं। पूरी नीति के लिए [SECURITY.md](SECURITY.md) देखें।

### ब्रेनस्टॉर्म मिशन

"एआई ब्रेनस्टॉर्मिंग" नहीं। ब्रेनस्टॉर्म मिशन कानून के तहत विशेषीकृत भूमिकाएं हैं, जिसमें ट्रैक करने योग्य असहमति और निर्णय-आधारित आउटपुट होता है।

```bash
roleos run "explore product directions for a developer tool discovery platform"
# → MISSION: Brainstorm (Structured Inquiry)
#   Chain: 4 Analysts (parallel) → Normalize → Cross-Examine → Rebut → Synthesize → Expand → Judge
```

**यह इसे अलग कैसे बनाता है:**

- **लेयर 1 (सत्य):** चार विश्लेषक भूमिका-देशी स्कीमा (संदर्भ मानचित्र, उपयोगकर्ता मूल्य मानचित्र, यांत्रिकी मानचित्र, स्थिति मानचित्र) उत्सर्जित करते हैं - साझा गद्य नहीं। प्रत्येक भूमिका अंधा-बिंदु-प्रबलित है: निषिद्ध वाक्यांश, निषिद्ध दावा प्रकार, फ़िल्टर किए गए इनपुट विभाजन। परमाणुओं में उत्पत्ति होती है। एक निर्देशित क्रॉस-परीक्षा ग्राफ लक्षित चुनौतियां उत्पन्न करता है। मूल विश्लेषक दबाव में बचाव, संकुचित या वापस लेते हैं।

- **लेयर 2 (रेंडर):** पांच विशिष्ट मानव आवाजें (सीमा ज्ञापन, फ़ील्ड नोट्स, सिस्टम स्केच, दावा संक्षिप्त, क्रॉस-परीक्षा प्रतिलेख) जिसमें शाब्दिक प्रतिबंध हैं जो आवाज अभिसरण को रोकते हैं। संश्लेषण सत्य का उपभोग करता है, कभी भी प्रस्तुत गद्य नहीं। दोनों परतें हमेशा उपलब्ध होती हैं।

- **कस्टडी श्रृंखला:** प्रस्तुत प्रत्येक वाक्य एक सत्य-आधारित तत्व से जुड़ा होता है। संश्लेषण निर्देशों में तत्वों का उल्लेख किया गया है। क्रॉस-परीक्षा वास्तविक दावा आईडी को लक्षित करती है। विवाद ग्राफ अंतिम उत्पाद है, न कि गद्य।

**सिद्ध:** v0.4 गोल्डन रन - पूरी कस्टडी श्रृंखला सत्यापित। पूरी कलाकृति श्रृंखला के लिए [`examples/golden-run.md`](examples/golden-run.md) देखें।

### गहन ऑडिट मिशन

यह केवल एक सतही स्कैन नहीं है। गहन ऑडिट मिशन **एक रिपॉजिटरी को सीमित घटकों में विभाजित करता है और रिपॉजिटरी के अपने निर्भरता ग्राफ द्वारा निर्धारित पैमाने पर विशेषज्ञ ऑडिटरों को नियुक्त करता है।**

```bash
roleos run "deep audit this repo" --manifest=audit-manifest.json
# → MISSION: Deep Audit (Manifest-Scaled)
#   Steps: Component Auditor ×6 + Test Truth Auditor ×6 + Seam Auditor ×8 + Synthesizer + Action Plan + Critic = 23 steps
```

**यह इसे अलग कैसे बनाता है:**

- **गतिशील वितरण** - कार्यकर्ता की संख्या निश्चित नहीं है। 5 सीमा समूहों वाले 10-घटक रिपॉजिटरी से 28 चरण उत्पन्न होते हैं (2×10 + 5 + 3)। 3-घटक रिपॉजिटरी 12 चरण उत्पन्न करता है। स्केलिंग सूत्र `2N + K + 3` है, जहाँ N = घटक, K = सीमाएँ।
- **मैनिफेस्ट-आधारित पैकेज** - एक `audit-manifest.json` घटकों (फ़ाइल पथों, पंक्ति गणनाओं, विवरणों के साथ) और सीमाओं (इंटरफ़ेस विवरणों के साथ) को परिभाषित करता है। प्रत्येक ऑडिटर को केवल अपना पैकेज प्राप्त होता है।
- **चार भूमिका प्रकार** - घटक ऑडिटर (प्रत्येक मॉड्यूल के लिए कोड सत्य), परीक्षण सत्य ऑडिटर (जो परीक्षण सिद्ध करते हैं बनाम जो मौजूद हैं), सीम ऑडिटर (निर्भरता ग्राफ से एकीकरण सीमाएँ), ऑडिट सिंथेसाइज़र (सभी पैकेजों से रैंक किया गया निष्कर्ष + कार्रवाई योजना)।
- **प्रत्येक चरण पर कलाकृति सत्यापन** - `validateArtifact()` दोनों निष्पादन पथों में प्रत्येक चरण के पूरा होने पर सक्रिय होता है। परिणाम चरण वस्तुओं से जुड़े होते हैं। सिस्टम जानता है कि क्या प्रत्येक कलाकृति ने अपने अनुबंध को पूरा किया।
- **ईमानदार आंशिक** - जब बजट या दायरा पूर्णता को रोकता है, तो प्रति-घटक निष्कर्ष व्यक्तिगत रूप से मान्य होते हैं। सिस्टम जो कुछ भी पूरा हो गया है, उससे संश्लेषित करता है, कभी भी पूर्ण कवरेज का झूठा दावा नहीं करता है।

**सिद्ध:** रनर-नेटिव प्रूफ रन - वास्तविक मैनिफेस्ट के विरुद्ध 18 परीक्षण, पूर्ण जीवनचक्र सत्यापित, जिसमें वृद्धि, पुन: खोलने और आंशिक विफलता शामिल है। 3/6/10/15-घटक मैनिफेस्ट के लिए स्केलिंग सूत्र सत्यापित।

### डॉगफूड स्वार्म मिशन

यह एक बार का लिनटर नहीं है। डॉगफूड स्वार्म मिशन **एक बहु-पास अभिसरण प्रोटोकॉल चलाता है जो एक रिपॉजिटरी को "काम करता है" से "उत्पादन के लिए तैयार" तक तीन स्वास्थ्य चरणों और पुनरावृत्त सुविधा वितरण के माध्यम से ले जाता है।**

```bash
roleos swarm
# → MISSION: Dogfood Swarm (Multi-Pass Convergence)
#   Stages: Health-A → Health-B → Health-C → Feature → Final
#   Domain agents: 3-5 parallel per wave (exclusive file ownership)
```

**यह इसे अलग कैसे बनाता है:**

- **तीन-चरण स्वास्थ्य पास** - चरण A बग और सुरक्षा मुद्दों को ठीक करता है (जब तक 0 गंभीर + 0 उच्च न हो जाए)। चरण B सक्रिय सख्तता लागू करता है (उपयोगकर्ता निष्कर्षों की समीक्षा करते हैं)। चरण C कोडबेस को मानवीय बनाता है - त्रुटि संदेश जो उपयोगकर्ताओं की मदद करते हैं, पुन: कनेक्शन प्रतिक्रिया, लोडिंग स्थिति, पहुंच क्षमता। प्रत्येक चरण एक अलग लेंस है, एक ही स्कैन को दोहराया नहीं जाता है।
- **अनन्य फ़ाइल स्वामित्व** - प्रत्येक डोमेन एजेंट `swarm-manifest.json` के माध्यम से विशिष्ट फ़ाइलों का मालिक होता है। कोई भी दो एजेंट एक ही फ़ाइल को संपादित नहीं करते हैं। कोई मर्ज संघर्ष नहीं। कोई समन्वय ओवरहेड नहीं।
- **बिल्ड गेट** - प्रत्येक लहर के बाद लिनटर + टाइपचेक + परीक्षण पास होना चाहिए। सिस्टम स्वचालित रूप से बिल्ड सिस्टम (नोड, रस्ट, पायथन, गो) का पता लगाता है और सही कमांड चलाता है।
- **उपयोगकर्ता चेकपॉइंट** - स्वास्थ्य-बी और सुविधा पास को निष्पादन से पहले स्पष्ट उपयोगकर्ता अनुमोदन की आवश्यकता होती है। सिस्टम निष्कर्ष प्रस्तुत करता है, उपयोगकर्ता यह तय करता है कि क्या बनाना है।
- **पुनरावृत्त अभिसरण** - चरण तब तक लूप करते हैं जब तक कि निकास शर्तें पूरी नहीं हो जातीं या अधिकतम पुनरावृत्तियों तक नहीं पहुंच जाती। पिछली फिक्स द्वारा पेश किए गए प्रतिगमन को पकड़ने के लिए प्रत्येक लहर खरोंच से पुन: ऑडिट करती है।
- **डोमेन ऑटो-डिटेक्शन** - `roleos swarm manifest --generate` रिपॉजिटरी प्रकार (सीएलआई, वेब, डेस्कटॉप, एमसीपी, मोनोरेपो) का पता लगाता है और गैर-अतिव्यापी डोमेन असाइनमेंट उत्पन्न करता है।
